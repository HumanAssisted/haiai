# Cross-Language Media Verify-Parity Fixtures

Pre-signed image and markdown fixtures used by the Rust, Python, Node, and Go
`cross_lang_media_*` tests. The same committed bytes must verify as `valid` in
all four SDKs. This is the media wire-parity contract (PRD §5.5,
MEDIA_SIGNING_TASK_011).

## Layout

- `_source/source.png`, `source.jpg`, `source.webp`, and `source.md` are the
  deterministic unsigned inputs.
- `signed.png`, `signed.jpg`, `signed.webp`, and `signed.md` are the current
  JACS v2-signed counterparts.
- `CHECKSUMS.txt` contains the SHA-256 watchdog for all four signed files.
- `SIGNER.json` records `signer_id`, `algorithm`, `public_key_file`,
  `verifier_agent_dir`, and the regenerator path.
- `signer.public.pem` is the ephemeral PQ signer's only retained key material.
- `verifier-agent/jacs.config.json` is the verifier's portable, signed v2
  config with relative `data` and `keys` paths.
- `verifier-agent/data/agent/<id>_<version>.json` is the verifier agent document;
  tests restore `_` to `:` after copying because `:` is illegal in Windows
  filenames.
- `verifier-agent/data/public_keys/<hash>.pem` and `<hash>.enc_type` are the
  verifier's local public-key cache.
- `verifier-agent/keys/jacs.public.pem` and `jacs.private.pem.enc` are its native
  Ed25519 test keys.
- `verifier-agent/keys/jacs.ecosystem.public.pem`,
  `jacs.ecosystem.private.pem.enc`, and `jacs.keyring.json` are its generated
  ecosystem compatibility key material and keyring metadata.

## Provenance and trust

Source images are deterministic flat-color pixels generated by the Rust
`image` crate (PNG and JPEG) plus a hand-built minimal RIFF/WebP container. The
markdown is plain ASCII. No third-party content is embedded.

The regenerator uses local JACS `0.11.4` to create an ephemeral `pq2025` signer
and emits `jacs-signature-v2` media/text signatures. The signer's config and
private key are discarded; only `signer.public.pem` is committed. Verification
stages that key as `<signer_id>.public.pem` and passes its directory explicitly,
so the tests exercise cross-agent PQ key resolution.

Go cannot create a JACS agent through its current CGo surface, so the generator
also commits a separate signed Ed25519 verifier agent. Its private and ecosystem
private files are encrypted test-only material with the known password
`MediaFixtureVerifierPass!123`. They are never production credentials, never a
trust anchor, and must never be copied into a deployment. The verifier identity
is different from the PQ signer and cannot forge these media fixtures.

No test enables unsigned-agent or legacy-signature compatibility flags.

## Regenerating

JACS signatures include timestamps, identities, and nonces, so an intentional
regeneration changes the signed bytes, checksums, signer identity, public key,
and verifier fixture. CI must not regenerate them.

From `rust/`:

```text
cargo test -p haiai --test regen_media_fixtures -- --ignored
```

The regenerator:

1. Recreates all four deterministic `_source` files.
2. Creates an ephemeral PQ signer with a current signed config.
3. Signs the four sources and writes `signer.public.pem`.
4. Creates the distinct portable signed Ed25519 verifier fixture.
5. Rewrites `CHECKSUMS.txt` and `SIGNER.json`.

Commit every changed/generated file listed in the layout together. Then run the
Rust, Python, Node, and CGo cross-language media suites; all valid and tampered
cases must agree before publishing.
